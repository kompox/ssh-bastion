# Task: DNS query rewrite proxy (replace dnsmasq)

## Background

The current local docker-compose topology uses dnsmasq with `cname=...` rules generated by the web app.

A known pain point is that alias resolution can depend on cache state (e.g. CNAME-only answers that require the client to chase CNAMEs). We want to avoid relying on client-side CNAME chasing by replacing dnsmasq with a minimal query-rewrite forwarder.

## Goal

- Replace the dnsmasq sidecar with a DNS forwarder implemented in `ssh-bastion`.
- Listen on UDP :53.
- For configured aliases, rewrite only the incoming QNAME and forward to an upstream resolver.
- Return the upstream response and rewrite the owner name back to the original QNAME for `A`/`AAAA` records only.
- Use a single `ssh-bastion serve` command with flags to select services (web only, DNS only, or both).

## Scope

### In

- Minimal UDP-only DNS service (no TCP support initially).
- Alias source/destination is driven by the existing web UI and storage (`aliases.json`).
- docker-compose updated to remove the dnsmasq container.
- E2E coverage for the new behavior (including the ProxyJump scenario).

### Out

- Implementing recursive resolution in-process (beyond forwarding to upstream).
- Implementing DNS caching.
- Implementing advanced DNS features (DNSSEC validation, DoH/DoT, etc.).

## Plan & Checklist

- [ ] Introduce `ssh-bastion serve` and flags to select services (web only, DNS only, or both).
- [ ] Implement UDP listener on :53 and forwarding to upstream (default to Docker DNS `127.0.0.11:53` in compose).
- [ ] Implement QNAME rewrite based on aliases.
- [ ] Implement response rewrite for A/AAAA owner name only (original QNAME).
- [ ] Update `compose.yml` to remove dnsmasq and ensure sshd uses the in-process DNS server.
